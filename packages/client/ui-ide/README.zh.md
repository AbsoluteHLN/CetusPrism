# @deepseek-ai/dsh-client-ui-ide

[English](README.md) | 中文

IDE 工作区界面：左侧是会话的项目文件树，中间是正在编辑的代码，右侧是同一个会话的助手对话——CetusPrism 的编码前端，沿用应用自身的设计语言。

IDE 属于**一个**会话。它的左栏是该会话的工作区，中间栏是正在编辑的文件，右栏是该会话的对话——共享对话内容的第二个、显式绑定的实例，与应用在中央区域显示的对话框彼此独立。

界面自带身份：三栏之上有一条标题栏，点明 IDE、绑定的会话与所展示的项目；每一栏还各有一条自己的栏头。因此它读起来像一张工作台，而不是一个挂了三条栏的对话页。代码栏是一个**编辑器**：文件归用户改动，改动会写回磁盘。

## 概要

<a id="use-this-package"></a>
## 使用这个包

### 工作区模型

`ide-model.ts` 承载工作区自身的状态：绑定的会话、已列出的目录层级、展开的目录，以及按标签顺序排列的已打开文件。每一次变化都是该状态上的纯函数，因此无需 Remote、文件系统或浏览器即可测试。

```ts
import { bindSession, openFile, closeFile, activeFile } from '@deepseek-ai/dsh-client-ui-ide/client'

let state = bindSession(state, sessionId, '/project', reference)
state = openFile(state, { path: '/project/a.ts', name: 'a.ts', language: 'typescript', content: '' })
state = closeFile(state, '/project/a.ts')
```

换一个会话绑定，工作区就从头开始——文件树与标签页条都属于那个会话的项目。再次绑定同一个会话则原样保留，因此离开后重新进入，工作区还在。重复打开同一个文件不会复制标签页；关闭当前标签页时，界面会交给相邻的标签页，而不是留下一片空白。

### 项目文件树

`ide-tree.ts` 把已列出的层级投影成左栏渲染的行：目录在前、文件在后，每组按名称排序，每一行都记录自己的层级。目录只在被打开时才列出，因此工作区里存的是用户真正看过的东西。过滤会保留命中项的祖先——父目录本身不匹配查询的文件依然可达，因为通向它的那条路径正是用户输入的内容——而且过滤状态下的树会遍历所有已列出的层级，不只是展开的那些。

文件树会**跟随**工作区：每个已列出的层级都会通过宿主的文件监视被**观察**，一次观察就会重新列举该层级，并重读它下面处于干净状态的已打开文件——Agent 的改动因此无需手动刷新就能到达文件树。编辑器处于脏状态的文件永远不会被重读覆盖——观察服务的是磁盘的事实，不是编辑器的——而失败的监视会安静退场，因为一棵靠手动刷新的树依然是一棵能用的树。

### 代码面

中间栏是一个**编辑器**，不是一张文件图片。`IdeCodeEditor` 把一个文字透明的文本区叠在高亮层上，因此插入符、选区与撤销栈仍归浏览器所有，而背后的源码穿着产品其他地方同一套语法高亮。代码视图必须做对的三件事，它都做对了：

- 文字**不换行**。一行源码就是一行；栏窄时横向滚动，而不是把一个词从中间劈开。
- 行号**不被裁切**。行号栏是独立的一栏，宽度足够放下该文件自己的行数，并随正文一起滚动。
- 代码**填满整栏**。栏里没有漂浮的卡片，文字四周也没有留白：这一栏就是代码。

Ctrl+S（Cmd+S）把文件写回；Tab 插入两个空格而不是离开代码面。插入符所在的行与列会报到状态栏，状态栏就贴在它描述的代码下方。

### 文件如何改动

一次编辑会让文件变**脏**：标签页上出现一个圆点，栏里出现保存按钮。写入时会带上编辑器读到的版本号，因此被 Agent 在编辑器底下改写过的文件会被拒绝而不是被覆盖——改动留在屏幕上，状态栏说明原因。写入被限制在该会话的工作区根目录内，并按该会话自己的沙箱模式执行：只读的会话根本改不了。重新读取也不会丢掉用户的改动：脏文件保留自己的编辑。

### 界面

`IdeWorkspace` 依据工作区服务渲染这三栏：左侧的项目文件树、中间的标签页条与编辑器、右侧的助手栏。它是一个受控组件：状态来自传入的 store，交互通过回调发出，因此同一套界面可以服务 Web 客户端、桌面外壳与测试。

三栏之上是标题栏：IDE 标识、所绑定会话的标题、以面包屑分段呈现的项目根目录，以及两个离开界面的动词——刷新与回到对话。它下面，`IdePaneHeader` 给每一栏同样的栏头结构：一个图标、栏名，以及这一栏最清楚的那项细节——项目根目录、当前文件的语言、会话标题。

文件树读起来像 IDE 的文件树：目录带着随状态变化的文件夹图标，文件带着各自的类型图标，已在标签页条里打开的文件保留一个标记，当前文件则戴上强调色。

三栏并非焊死的。中栏两侧各有一条分隔条，拖动（也可用方向键）即可调整那一栏的宽度；文件栏还能整体收成一条图标窄条。**宽度首先属于编辑器**：代码栏才是这张工作台存在的理由，因此每一侧栏都按它在这帧里的比例封顶，只要还有侧栏能让位，代码栏就保住自己的下限。先让位的是文件树，其次是助手栏，代码栏最后。助手栏还能一键收成自己的图标窄条。布局记在本地，用户调好的宽度下次进来还在。

### 入口

IDE 是从**会话**进入的，而不是从导航栏。插件把界面以键 `ide` 注册在布局的中央面板，同时在每个会话行上注册一个菜单项与一个行内按钮：点一下就为该会话打开 IDE，把工作区绑定到它的项目，并在代码旁边显示它的对话。

IDE 接管整帧：IDE 在场时应用自身的左侧栏会收起，离开时还原——因为这张工作台是文件树、代码与助手栏，而不是文件树、代码、助手栏再加一层导航。布局接口说明自己要的是哪种状态（`ctx.layout.setSidebarCollapsed`），因为「切换」分不清「进入」与「离开」。

<a id="understand-the-implementation"></a>
## 理解实现

### 服务与文件数据源

`createIdeWorkspace()` 拥有状态与动作动词。文件本身来自宿主端的 `workspaceFiles` Remote 命名空间，并绑定到工作区所属的会话：

```ts
const workspace = createIdeWorkspace(createFilesPort(ctx.remote))
workspace.bind(sessionId, cwd, reference)
```

目录列举使用工作区路径，并被限制在该会话的工作区根目录内；文件读取遵循组合文件系统的读取权限，且是分页的，因为整个文件可能超过一页。同一个路径同一时刻只有一次列举或读取生效：再次请求会作废仍在飞行中的那次请求。

同一个命名空间也承载**写入**。`workspaceFiles.write` 在该会话自己的沙箱模式下替换某个文件的文本，以调用方读到的版本号作守卫，并被限制在该会话的工作区根目录内——读取可以越出工作区，编辑不行。它是读取权限的例外，也是这个命名空间里唯一会改动东西的路径。

同一个命名空间也承载**观察**。`workspaceFiles.changes` 通过 Remote 的受监管流推送一个目录的文件系统通知——每个已列出的层级一条监视，层级落定时打开，绑定消失时结束。

### 助手栏

右栏以 `embedded` 变体渲染**共享的**对话内容，并绑定到明确的会话。对话本身没有在这里重写——消息流、输入框与视图都由共享的内容工厂负责；这一栏只决定它在**为哪个会话**说话。

这一栏向共享内容索取**精简版**输入框：只有文本区、命令按钮与发送按钮，没有别的。访问模式、抢前台（computer use）投递开关、标准模式与后端、计划模式、模型选择器与指标行都属于产品自己的对话面板——把它们再复制一份塞进侧栏只是噪音，而抢前台开关更不该出现在代码视图旁边。精简是宿主显式要来的：`variant: 'embedded'` 在侧栏 subagent 对话那里含义不变，主面板也从不索取精简版。这一栏默认 420px，比它旁边的文件树更窄，因为它装的东西更少。

这一栏像侧栏的 subagent 对话那样，把这段对话放进一个自身有确定高度的 flex 盒子里，于是滚动归对话所有：消息在输入框下方滚动，输入框始终固定在栏底，这一栏自己不会整块一起滚动。

### 皮肤

界面穿的是应用自身的令牌层（`--dsw-*`），因此它跟随当前主题——浅色或深色、Folio 或经典配色——不需要自己另立一套颜色。几何取柔和的那一套：4px 控件、6px 卡片、发丝级分隔线而非投影，只有一个强调色留给真正「当前」的元素。

比令牌更重要的是**形状**也取自产品本身，IDE 因此读起来是 CetusPrism 的一个面板，而不是另起炉灶的产品套了层代码编辑器的皮。它的标题栏就是对话头部的几何：一行、左右 20/28px 内边距、底下 0.5px 的 l3 细线，会话名是当前面包屑、项目路径是它的祖先面包屑，以 `/` 分隔。它的栏头是分区标签——13px 次级文字、14px 线性图标、幽灵按钮——背后没有色带、底下没有分隔线。它的标签页就是对话的视图标签：13px/500、三级灰，当前项以 business-primary 加 2px 下划线。它的文件树行就是侧栏的行：radius-md 加交互态填充，悬停行与当前行同等待遇。它的状态栏就是输入框下方的指标行：平贴、12px、三级灰。

<a id="model-experience"></a>
## 模型体验

作为纯浏览器端的 IDE 界面，它不注册任何工具、提示词段落或会话事件。

#### KV Cache effect

界面渲染它读到的文件，把改过的文件写回去，并重新渲染该会话的对话；它展示的内容不会进入任何模型请求，打开或编辑文件也不改变会话状态。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 一次文件读取最多走四页、每页五千行，超出部分不会显示，界面会明确说明。
- IDE 同时只保留一个被持有的会话；绑定另一个会话会释放前一个。
- 一次写入替换整个文件：没有补丁、没有多文件编辑，也没有重命名。
